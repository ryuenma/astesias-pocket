# Astesia's Pocket — project rules

GPL-3.0 fork of Ivy Wallet. Personal-use, two profiles (owner + SO),
sideload-only. Repo is the wallet app; the PocketBase sync server is a
**separate, non-git** directory and is out of scope unless explicitly asked.

## Skills that MUST be loaded for this project

Load these before starting work, not after something breaks. Each one is here
because a defect in this repo already matched it:

| Skill | The defect that put it here |
|---|---|
| `systematic-debugging` | Three bugs of one shape took ~10 hours. They were fixed by pattern-matching symptoms instead of finding the root cause. **Understand before fixing.** |
| `silent-failure-triage` | A save ended in `catch (e: Exception) { e.printStackTrace() }` and closed the screen as if it had worked. Money had moved and the ledger recorded nothing. Use it whenever a run "did nothing". |
| `test-integrity` | 476 unit tests green while the feature was unreachable from its own button. Before trusting a green suite, check what it actually exercises. |
| `physical-device-test-runs` | Device taps were invented from `[0,0][0,0]` bounds and reported as verified. Real hardware has rules. |
| `design-claim-verification` | Two false claims were made in one session (a contamination alarm that was wrong, and a tap that never fired). Verify a finding before recording or fixing it. |
| `ponytail` | Minimal change. Fewest files, reuse existing helpers, root-cause fix, `ponytail:` comment naming the ceiling, ONE runnable check for non-trivial logic. |
| `astesia-pocket-gotchas` | 25 repo-specific traps. **Read this first.** |

Also situational: `offline-first-sync-architecture` and
`idempotency-needs-two-halves` before touching the outbox/publish/directory;
`typed-http-client-integration` for the PocketBase JSON decode errors.

## Non-negotiables

- **Read `astesia-pocket-gotchas` before building or debugging.** It covers the
  Gradle "BUILD SUCCESSFUL when nothing ran" trap, the detekt baseline IDs, the
  Room migration helper, CRLF/`git show` hazards, and the POCO device quirks.
- **A green Gradle line is not evidence.** Read `TEST-*.xml` and report
  tests/failures with the denominator.
- **Never report a UI result you cannot see.** Back it with a screenshot, a
  database row pulled from the device, or the owner's own words. When a control
  reports `[0,0][0,0]`, ask the owner to tap it rather than guessing coordinates.
- **Never run `git stash`/`checkout`/`reset`/`worktree`** — other agents may
  share this repo. Use `git show HEAD:<path>` into scratch instead.
- **Money is `Double`.** Not `BigDecimal`.
- **The owner's real data must stay untouched.** Test with the synthetic
  fixtures; `so.db` and `ivywallet.db` both holding 6538 rows is by design, not
  contamination.
- Indonesian (`values-id`) and English (`values`) strings are both required for
  any user-visible text, placeholders (`%1$s`/`%1$d`) preserved.

## Build & verify

```bash
export JAVA_HOME='F:\Android Emulator\jdk\jdk-17.0.20.1+1'
export ANDROID_HOME='F:\Android Emulator\sdk'

# unit tests — delete results first, then read the XML
rm -rf <module>/build/test-results/testDebugUnitTest
./gradlew :shared:data:core:testDebugUnitTest :shared:domain:testDebugUnitTest \
           :temp:legacy-code:testDebugUnitTest

# device install
"$ANDROID_HOME/platform-tools/adb.exe" -s 8f03f167 install -r -t \
    app/build/outputs/apk/debug/app-debug.apk
```

Devices: POCOPHONE_F1 `8f03f167` (Android 10/API 29 — visual checks, check
`mCurrentFocus` for the StatusBar wedge first) and AVD `astesia_a`, which
enumerates as **`emulator-5554`**.
